# 27. RBC NOB θ_c — 아랫벽 dW 벽면 증분 누수 버그 발견·수정 (E2 판정 + E4 검증)

> **작성**: 2026-07-03 (Report/25 → 26의 후속)
> **결론(요약)**: E2(z-256)가 판정을 냈다 — **θ_c는 128-z에서 격자 수렴이 아니었다**
> (inst 0.046 플래토 → 256-z에서 0.055+ 상승 지속). 원인을 코드 수준으로 추적한 결과,
> **아랫벽 W-면(내부 인덱스 k=h)의 미클램프 dW 증분이 블록 결합을 통해 dU로 누수**되어
> 아랫벽 첫 셀에 U 스파이크(rms의 ~200배)를 만들고, 이것이 hot-벽 열경계층 안에 앉아
> NOB 비대칭을 오염시키는 결함을 확인·수정했다(CPU+GPU). 검증 런 E4 제출.

## 1. E2 판정 — z-해상도가 θ_c를 바꾼다

| | 128³ (γ=2.6) | E2: 128×128×256 (γ=2.6) |
|---|---|---|
| inst θ_c | 0.046±0.002 (t≳4000 플래토) | 0.0473→0.0490→0.0516→**0.0551 @t=8000 (스냅샷 확정), 단조 상승 중** |
| χ_θ (슬로프 두께비) | 1.20 | **1.26** |
| Nu | 10.8 | 10.5 |

256-z가 아직 미수렴(상승 중)이므로 E2b로 t=12000까지 연장해 플래토를 확정한다.
0.074 도달 여부가 관건.

### 1.1 필드 포렌식 — 아랫벽 U 스파이크

세 restart 필드의 층별 최대 |U| (rms는 세 경우 모두 ~0.0025로 동일 = 벌크 유동 동일):

| 런 | k=0 (아랫벽 첫 셀) | k=1 | 벌크 max | 윗벽 3층 |
|----|------------------|-----|---------|---------|
| 128³ NOB (t=7185) | **0.536** | 0.038 | 0.030 | 0.002 |
| 128³ OB (E1a, t=970) | **0.963** | 0.056 | 0.049 | 0.002 |
| **256-z NOB (E2, t=8000)** | **0.0033** | 0.0019 | 0.0074 | 0.0016 |

시그니처: **아랫벽 전용**(윗벽 조용) · **U 위주**(V는 완만) · **OB에서도 발생**(μ̂ 비대칭과 무관)
· **256-z에서 소멸**. no-slip이면 첫 셀이 가장 작아야 하는데 40~200× 크다. 이 스파이크는
z=0.0015, 즉 열경계층(λ≈0.04) 깊숙이 앉아 hot-벽 경계층을 지속적으로 교란한다 —
θ_c(=경계층 비대칭)가 낮게 나온 직접적 기전 후보.

## 2. 코드 결함 — dW 아랫벽 면 증분 누수

MAC 격자에서 W는 z-면 중심: **아랫벽 W-면은 내부 인덱스 k=h에 있고, 윗벽 면은 고스트
슬롯에 있다** (기지 사항 — 기존 워크어라운드: 시간루프에서 `mom_W.step()` **후** `W[i,j,h]=0`).

문제는 모멘텀 솔버 **내부**다 (`solve_momentum_var_{cpu,gpu}`):

1. dW의 z-스윕(`k_mom_adi_var`, z_staggered)은 k=h 행(=벽면)을 일반 행처럼 풀어
   **0이 아닌 벽면 증분 dW[k=h]** 를 남긴다 (벽면 W는 핀인데).
2. 이 미클램프 dW를 `couple_dd_dV_var`(dV의 RHS)와 `block_couple_dU_var`(dU 보정)가
   소비한다. 특히 M12 항:
   ```
   dU[c] -= dt·[ 0.25·(dWm5·dUdz5 + …) − 0.5·Cmu·irc/dx3·(…) ]
   dUdz5 = (U[c] − U[ghost])/dmx3[h]     ← 벽 전단, 1/dmx3 ≈ 300 증폭
   dWm5  = dW(k=h 면 평균)               ← 미클램프 벽면 증분!
   ```
   → 아랫벽 첫 셀 dU에 스퓨리어스 주입.
3. **윗벽은 무사**: 윗벽 W-면이 고스트 슬롯이라 dW가 0 → 관측된 상하 비대칭과 정확히 일치.
   V는 M32(y-미분, 벽 증폭 없음)라 완만 → U≫V도 일치. OB에서도 발생(블록 결합은 μ̂와
   무관하게 존재) → 일치. 기존 W[h]=0 워크어라운드는 스텝 **끝**에 적용되므로 이 내부
   누수를 막지 못한다.

256-z에서 소멸하는 것은 벽 셀이 얇아지며 누수-피드백(스파이크→대류→dW 잔차)이 임계
아래로 내려가는 것으로 해석된다(따라서 128-z에서만 발현하는 해상도-트리거 결함).

## 3. 수정 (2026-07-03)

dW가 소비되기 전 두 지점에서 아랫벽 면 증분을 핀:

- **CPU** `src/equation/momentum/cpu/momentum_cpu.cpp` — `zero_dw_lower_wall_face()` 추가;
  dW z-스윕 직후 + `block_couple_dW_var` 직후 호출.
- **GPU** `src/equation/momentum/gpu/momentum_gpu.cu` — `k_zero_dw_wall_face` 커널 추가;
  같은 두 지점에서 호출 (z-벽 & lower-rank 소유 시).

적용 조건: z가 wall이고 해당 랭크가 아랫벽 소유일 때만. 주기/비벽 케이스 무영향.
CPU 빌드 검증 완료. (근본 해법은 memory 노트대로 modify_tdma_row에 stagger 플래그를
넣어 k=h 행을 항등행으로 만드는 것 — 이번 핀은 동등한 효과의 최소 수정.)

  z-512 또는 γ 상향으로 마무리.

## 6. E2b·E4 결과 (2026-07-03 판독)

**E2b (256-z 연장)**: 누적 Theta_c가 t=8750부터 평평 — **inst θ_c = 0.0555 ± 0.001로 플래토
확정**. 256-z의 수렴값은 0.074가 아니다.

**E4 (128³ + dW 벽면 핀, 스파이크 상태에서 웜스타트)**:
- **스파이크 제거 성공의 간접 증거: dt가 0.0155 → 0.02(캡)로 상승** (+29% 처리량) — 이전에는
  스파이크 u≈0.54가 CFL을 지배했었다. (restart_e4_dwfix의 k=0 층 직접 확인은 쓰기 완료 후.)
- 그러나 θ_c는 **inst ≈ 0.042–0.043** — 수정 전(0.046)보다 오히려 소폭 낮다.

**해석**: 스파이크는 z-저해상도의 *증상*이었고 θ_c를 (순효과로는 약간 올리는 쪽으로) 오염했을
뿐, 결손의 주범이 아니다. 수정은 그 자체로 옳고(스퓨리어스 벽 슬립 제거 + dt 이득) 유지한다.
**결손의 실체는 순수한 z-해상도 수렴**으로 좁혀졌다:

| z (클린 상태) | inst θ_c |
|---|---|
| 128 (E4, 수정 후) | 0.0425 |
| 256 (E2b) | 0.0555 |
| Richardson 외삽 p=1 | ≈ 0.069 |
| Richardson 외삽 p=2 | ≈ 0.060 |
| 참조 (Kim/Horn) | 0.0744 |

→ **E5 (z-512, 수정 바이너리, job 29955)가 최종 판정**: θ_c(512) ≈ 0.062–0.065면 외삽이
참조와 정합(결손 = z-해상도 + 벽면 버그로 종결), ~0.057 포화면 저장소≠프로덕션으로 복귀.
초기장은 E2 t=8000 필드의 z-보간(`restart_e3_z512_init/`), 통계 창 t=8500–11000.

참고: Kim 2023이 같은 공칭 128³(ny=128)로 0.0744를 얻었다는 점은, E5가 해상도 스토리를
확정할 경우 "Kim의 벽면 클러스터링(스트레칭)이 우리 γ=2.6보다 강했거나, 프로덕션 코드의
벽 근방 이산화가 달랐다"는 후속 질문을 남긴다 — Pan et al. 2022 원문에서 격자 상세 확인 필요.
