> **작성**: 2026-07-05 (Report/27 dW 벽면 버그, Report/28 §6.3 윗벽 발견의 후속)

## 2. 근본 원인 — PaScaL의 벽 마스크 구조 vs 포트

### 2.1 PaScaL (module_solve_momentum.f90 solvedU, 280–410행; solvedW 유사 503/529)

벽수직(x2) 방향에서 벽 인접 행(jum=jC_BC(jm)=0 또는 jup=jC_BC(jp)=0):

```fortran
! (a) 델타폼 교차 결합 — 벽쪽 항 드롭 (402-403행)
RHS -= ( 0.25*(v4*jup*dudy4 + v3*jum*dudy3)
       - invRhocCmu_half/dx2(j)*(mu4*dvdx4*jup - mu3*dvdx3*jum) )
! (b) 밴드 계수 — 순수 드롭, 폴드 없음 (385-386행); 대각 mACJ는 벽 점성 유지
mAPJ = mAPJ*jup ;  mAMJ = mAMJ*jum      ! −M·qⁿ 잔차와 ap/am 매트릭스 양쪽에 적용
! (c) 벽 기여 재도입 — 명시 경계항 (367행): no-slip 벽(UBC=VBC=0)이면 전부 0
RHS += (1−jum)*ubc_down + (1−jup)*ubc_up
```

즉 **no-slip 벽에서는 "벽 인접 행의 벽쪽 대류·교차응력·오프대각을 그냥 떨어뜨리는 것"이
PaScaL의 이산화**다. (명시 점성항 viscous_u2의 벽 전단은 붕괴-고스트 좌표에서 유지 —
벽 마찰은 대각/명시 확산으로 남음.)

### 2.2 포트 — 마스크 전무 (확인 완료)

`momentum_gpu.cu`의 모든 커널이 벽 인접 행에서 **고스트 값으로 풀 스텐실** 계산:
- `k_mom_rhs_var`: (a)의 z-방향 대응 항(0.25·w·dqdz, inh/dx3·(muz·dwdx)) 및 −M·qⁿ의
  mAPK/mAMK — 마스크 없음. antisymmetric 고스트면 벽쪽 항이 0이 아니라 내부값의 2배.
- `k_dd_dU`(376-383) / `k_dd_dW_var`(767-808) / `k_dd_dV_var` / `k_block_dW_var` /
  `k_block_dU_var`: 벽 인접 행에서 1/dmx₃(벽)≈650 증폭 결합을 그대로 계산.
- 밴드는 `k_modify_tdma_row_gpu`가 닫지만, RBC 설정(U/V antisymmetric → kind 1)은
  B∓=A **폴드**라 PaScaL의 순수 드롭(kind 0 동등)과 다름.
- CPU 미러(momentum_var_kernels_cpu.cpp)도 동일 누락.

### 2.3 불안정 메커니즘 (관측과 정합)

벽 인접 U행 ↔ 벽 인접 W면이 미마스크 교차 결합(양쪽 모두 1/dz_wall 증폭)으로 상호 펌핑.
플룸 충돌부의 강한 국소 전단이 시드 → 2Δx 모드가 dt-비례 진폭으로 포화. 발현이 임계형
(128³ 아랫벽 → 256-z 소멸 → h-256 윗벽)인 것은 루프 이득이 국소 상태·격자 의존이기 때문.
Report/27의 dW 핀 = 아랫벽의 가장 강한 시드(벽면 dW) 제거 — 부분 수정이었음.

## 3. 수술 명세 (z-벽 마스크 kum/kup 도입)

정의: cell-centered(U,V) 행 기준 kum=0 ⇔ k=h(하벽 소유 랭크), kup=0 ⇔ k=n3i+h−1(상벽).
W(면 중심)는 벽면 행 자체가 핀(하: k=h — Report/27; 상: 고스트) + 인접 면 행에 동일 마스크.

| # | 위치 | 수정 |
|---|------|------|
| A | `k_mom_rhs_var` (U,V,W 각각) | z-방향: 0.25·(w6·**kup**·dqdz6 + w5·**kum**·dqdz5); inh/dx3·(muz6·dwdx6·**kup** − muz5·dwdx5·**kum**); −M·qⁿ의 mAPK·**kup**, mAMK·**kum** (PaScaL (a),(b) 대응) |
| B | `k_mom_adi_var` z-스윕 밴드 | 현 modify_row 유지하되 U/V도 순수 드롭(kind 0) 사용 — `ghost_uv="zero"` (E8에서 이미 옵션화) |
| C | `k_dd_dW_var`, `k_dd_dV_var` | ddudz/ddw 등 z-벽 인접 결합 항 ×kum/kup |
| D | `k_block_dW_var`, `k_block_dU_var` | M12/M32의 z-벽 인접 레그(dWm·dUdz, muz·dWmx 등) ×kum/kup |
| E | CPU 미러 (momentum_var_kernels_cpu.cpp의 대응 함수들) | 동일 |
| F | 커널 시그니처에 owns_lower/owns_upper 전달 (main→solve→kernels) | — |

**검증 프로토콜 (E8c)**: 수정 바이너리로 E7b 스파이크 상태 재시작 → (i) umax 0.47 → ~0.01
즉시 붕괴 (CFL 0.3에서), (ii) div 유지 ~1e-10, (iii) 128³ 짧은 런에서 DHVC/RBC 기존 결과
비회귀(θ_c/Nu ±1%). 통과 시 E7c 재개(+CFL 상향 재시도 — 스파이크 제거 시 max(c)=5.2라
dt 캡 0.03 개방 = 6배 가속).

## 5. E8c 결과와 §2–3의 정정 (2026-07-05 저녁)

**E8c(W 벽면 항등행 + ghost_uv=zero, jobs 29998→29999): 기각** — umax 0.44–0.47 유지.
(항등행·zero-ghost는 아랫벽 구조의 올바른 경화이므로 **유지**한다. 사후 핀보다 정확하고
PaScaL의 j_indexS 행 제외와 등가.)

**§2–3의 정정**: blockLdU(1418-1426행)와 solvedW(1025-1031, 1119-1120행)의 마스크를 정독한
결과, PaScaL의 jup/jum/jwp/jwm 마스크는 **벽면 증분·벽면 속도(=정확히 0)가 곱해지는 레그만
죽이는 이중 안전장치**다. 상벽 인접 행의 내부-면 레그(예: blockLdU의 dvm3, jum=1)는 PaScaL도
유지한다. 따라서 **no-slip 벽에서 포트는 (벽면 값들이 정확히 0인 한) 항 수준으로 PaScaL과
등가**이며, "마스크 누락"은 상벽 펌프의 원인이 아니다. 본 보고서 §2.3의 메커니즘 서술 중
"미마스크 결합" 부분은 이 정정에 따라 무효.

**남는 사실**: 상벽 U행의 2Δx 체커보드 + 마지막 내부 W-면의 스퓨리어스 유속(도메인 최대)은
h-256에서 지속 발화하며, 고스트 정책(E8)·dt(E8b)·벽면 항등행(E8c) 모두에 불감. 자극원 미상.

항 단위 코드 대조가 소진됐으므로 실측으로 전환한다:
1. `solve_momentum_var_gpu`의 각 스테이지(assemble 후 / 각 스윕 후 / block couple 후)와

3. 해당 스테이지의 항을 하나씩 꺼서(비활성) 펌프 레그 확정 → PaScaL 대응 코드와 최종 대조.

병행 확인 항목: 투영(δp의 상벽 행 2Δx 모드 여부 — 상벽 셀의 div 조립에서 W ghost 사용 확인),
FFT Poisson의 상벽 행 경계 계수, T-클리핑(현재 min=−0.498로 비활성 — 용의선상 하위).

## 7. E9 계측 비섹션 결과 — 원인 확정과 안정화 (2026-07-06)

§6 계획을 실행했다. 결론: **상벽 체커보드 = 명시적 블록 커플링 보정(delta-form 교차속도
항, k_block_dW_var/k_block_dU_var)의 한계안정성 불안정**. 콜드월 경계층(μ̃ 큼 + Δz 미세 +
플룸 충돌 전단)에서 루프 이득이 1을 넘나들며 CFL-비례 진폭으로 포화한다. 보정을 전역
균일 θ=0.5로 언더릴랙스하면 이득<1이 되어 스파이크가 완전 소멸한다.

### 7.1 계측 장치 (momentum_gpu.cu, env-게이트)
- `MPMSTD_MOMDBG=1`: 각 스테이지(rhs 조립/스윕별/블록 후/업데이트 후/투영 후)에서
  상벽 슬랩(마지막 6 내부 k-면) vs 벌크의 max|f| + 정렬도 g=⟨df,f⟩/⟨f,f⟩ 출력.
  g>0 = 해당 스테이지가 스파이크 패턴을 펌핑, g<0 = 감쇠.
- `MPMSTD_MOMDBG=2`: |U|,|W| 전역 argmax 위치(i,j,k) 추가 출력.
- `MPMSTD_BLKMASK_TOP=n`: 블록 커플링을 상위 n개 k-면에서 no-op으로 (진단용).
- `MPMSTD_BLKRELAX=θ`: 블록 커플링 보정을 전역 균일 θ배로 (안정화).
- **nvc++ 함정**: `-cuda -gpu=cc80`에서 `atomicMax(unsigned long long*)`가 조용히
  no-op (atomicAdd는 정상; 최소재현으로 검증). atomicCAS 루프로 대체해야 한다.

### 7.3 마스크 실험 (E9b/c/d/e) — 펌프 위치·이동성
- **6면/16면 no-op**: 슬랩 내 U 0.41→0.005 단조 붕괴(~30스텝, dt 캡 회복 ✓). 그러나
  전역 umax는 90스텝 후 0.4-0.5로 재성장 — argmax 판독(E9e) 결과 **재성장 위치 =

- 함의: 공간 마스크는 불안정을 "옮길" 뿐. 스킴 수준 완화가 필요.

## 4. 함의

- **E7/E7b의 θ_c(0.061–0.066)는 이 아티팩트 오염 하의 값** — 수정 후 재측정 필요.
  오염이 cold-BL을 교란해 θ_c를 낮추는 방향이었다면, 수정 후 값은 프로덕션(0.071)에
  더 근접할 것으로 기대.
- 이 마스크 구조는 DHVC에도 동일하게 적용됨(물성≡1이어도 대류 마스크는 유효) —
  DHVC 검증 결과의 재확인도 수정 후 회귀 테스트에 포함할 것.
- 스칼라 jep/jem(수정 완료) + 모멘텀 jup/jum(본 건) — "PaScaL의 벽 인접 행 마스크
  구조"가 이식에서 계통적으로 누락됐던 것. 부록 B(mbc/ebc/cbc)와 함께 이번 수술로
  벽 행 처리의 이식 충실도가 완결된다.
