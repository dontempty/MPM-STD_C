## 2. build_z 가 느린 이유

필드는 k 가 가장 빠른 레이아웃(`idx = (i·ny + j)·nz + k`), PaScaL_TDMA 밴드는 풀이 축이 가장 바깥인 레이아웃(`[sys + row·nsys]`).
x·y 스윕은 sys 에 k 가 들어 있어 두 순서가 같지만, **z 스윕은 row = k 라 두 레이아웃이 (j,k) 전치 관계**다.

```
z 밴드  p   = k·(nx·ny) + i·ny + j     j 가 가장 빠름
필드    idx = i·(ny·nz) + j·nz + k     k 가 가장 빠름
```

기존 공용 `build_kernel` 은 밴드 순서(j 연속)로 스레드를 놓아 쓰기는 연속이지만, 계수 식 `sweep_band` 의 필드 로드 10여 개가 전부
nz 보폭(≈2 KB)으로 흩어졌다 — 워프 하나가 로드마다 캐시라인 32개를 건드린다. L2 가 큰 H200 은 일부 가려 주고(2–4 배), 작은 V100 은 그대로 드러난다(10 배).

## 3. 어떻게 고쳤나 — `build_kernel_z` (`src/equation/momentum/system/system.cu`)

z 전용 커널을 분리하고 공유 메모리로 (j,k) 타일을 전치한다. 블록 = i 하나 + 32×32 타일, 스레드 32×8.
1. 연속 스레드 = 연속 k 로 필드를 읽어 `sweep_band` 를 계산, 결과 A·B·C·D 를 공유 메모리 타일(32×33, 뱅크 충돌 방지)에 둔다 → 모든 로드 병합.
2. 타일을 전치해 연속 스레드 = 연속 j 로 밴드에 쓴다 → 저장 병합.

계수 식·밴드 레이아웃·PaScaL 호출은 불변이라 **결과는 비트 동일** (스모크 FINAL θ_c 0.01503 / Nu 46.0360 전후 일치, 200 스텝 모니터 전 열 일치).
런처를 `launch_xy` / `launch_z` 로 나눠 두어 나중에 x·y 도 축별 커널로 쪼갤 수 있다. 상수물성 판도 같은 커널.

## 5. 2회차 — 랭크 내 순환 Thomas 커널을 레지스터 두 행 버퍼링으로 (2026-10-17)

(`pascal_tdma_cuda.cu`) 이 돈다. 논문(PaScaL_TDMA 2.1, CPC 2026) 커널은 이전 행을 레지스터에 들고 가 행당 로드 4회인데,
이 커널은 c·d·z[j−1] 를 전역에서 다시 읽고 보조 RHS `z` 를 0 으로 채우는 패스가 따로 있어 행당 전역 접근 ~22회였다.

b 는 쓰지 않음. 행당 접근 22 → 15. 산술 식·순서 동일 → 비트 동일 (게이트 통과: 스모크 FINAL·400 스텝 모니터 전 열 일치).

## 6. 3회차 (시도 후 제외) — 조각 분할 순환 Thomas (Thomas–축소계 하이브리드, 2026-10-17)

> **본 코드에서 뺐다 (사용자 결정).** 본런 격자(512³+)에서 이득이 2~3 % 뿐이고 코드만 복잡해진다. 작은 격자 × 여러 GPU 에서만 효과.
> 코드는 `apps/rbc_nob/scalability/backup/` (전체 .cu + patch) 에 백업, 아래는 기록. 본 코드는 2회차(순환 커널을 논문 커널과 같은 꼴로)까지.

**문제**: 2회차 뒤에도 라인(시스템) 수가 적으면 x·y TDMA 가 바닥에 걸린다 (H200 256³ np 4: 16k 라인, 호출당 0.46 ms vs 이상 0.17).
스레드 = 라인 하나라 병렬도가 라인 수에 묶여 GPU 가 빈다.

**변경** (`pascal_tdma_cuda.cu` `tdma_cycl_segmented_kernel`, nprocs = 1 순환 경로): 라인 하나를 p 조각으로 잘라 스레드 p 개가 나눠 푼다.
PaScaL 이 MPI 랭크 사이에서 하는 3단계를 한 블록(32 라인 × p) 안에서 — A. 조각마다 수정 Thomas(`tdma_modified_kernel` 의 식, 경계 행 2개는 공유 메모리),
B. 라인당 2p 행 순환 축소계를 스레드 하나가 공유 메모리에서 풀기, C. 조각마다 복원(`pascal_update_kernel` 의 식).
주기 경계가 축소계의 순환으로 처리되어 Sherman–Morrison 보조 RHS 가 없어진다(원소당 전역 접근 11회). 산술 순서가 달라 게이트는 허용오차(`check_gate.py`, 모니터 출력 정밀도에서 일치).

- ② 밴드 핑퐁: `build_y`(source = x 밴드 D0, `SourceLayout::BandX`) → D1, `build_z`(source = y 밴드 D1, `BandY`) → D0. scatter_x/y·stage 버퍼 사용 없음.
- ③ dW 의 scatter_z 가 δW 를 쓰면서 W += δW (이후 block_couple_v/u 는 δW 만 읽는다). δU·δV 는 커플링이 U·V 이웃을 읽으므로 add_increment 유지 (1.53 → 1.02).
