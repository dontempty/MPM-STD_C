# rbc_nob 전체 스텝 측정 — 어디에 시간이 가는가 (2026-10-17)

`apps/rbc_nob/main.cpp` 의 시간 루프를 호출 단위 17 구간으로 재고(plan.md §1·§2), 256³·512³ strong / weak 를 1노드 np ≤ 4 로 돌렸다.
200 스텝 중 워밍업 50 제외, 반복 2–3회 중 step_total 중앙값 런. 단위 ms/step(랭크 max). 수치 게이트: np·하드웨어에 무관하게 모니터 값 동일.

## 2. Strong / weak 효율 (np 1 → 4)

| | H200 256³ | H200 512³ | V100 256³ | H200 weak 256³/랭크 | V100 weak 256³/랭크 |
|---|---|---|---|---|---|
| np 2 | 80 % | 95 % | 104 % | 94 % | 96 % |
| np 4 | **61 %** | 90 % | 94 % | 93 % | 90 % |

np 4 에서의 확장 손실(= np 를 늘려도 안 줄어드는 양)은 어디서나 momentum_solve 가 1위, scalar_solve 가 2위. 통신(TDMA Alltoallv·halo)은 0.3–2 ms 로 아직 주범이 아니다.

## 2b. np 8 (V100 gpu04 8장, 현재 바이너리) — halo 자기 전송 수정 전/후

| 256³ step_total | np 4 | np 8 | 효율 np 8 |
|---|---|---|---|
| strong 수정 전 → 후 | 39.4 → 36.1 | 41.0 → 31.5 | 36 → 47 % |
| weak 수정 전 → 후 | 142 → 130 | 210 → 137 | 57 → **86 %** |

np 8 에서 늘어나던 halo 시간(weak 71 ms/스텝)은 하드웨어가 아니라 **주기 축(x·y)에서 이웃이 자기 자신일 때 MPI_Sendrecv 를 자기에게 보내던 코드** 때문이었다
(`scalar_scalability.md` §4, `subdomain_halo.cu` 수정, 비트 동일). 남은 np 8 손실은 분산 TDMA 의 Alltoallv (스텝의 1/3) 와 랭크당 격자가 작은 데서 오는 x·y TDMA 바닥.

## 2d. momentum_rhs 최적화 (2026-10-17 밤) — 나눗셈 제거 · 패스 융합 · (coarsening 은 제외)

momentum_rhs(이송·확산 스텐실 3 + 부력 + ∇P, 스텝의 15–22 %)는 메모리가 아니라 **FP64 나눗셈(셀당 ~58회)과 점유율(레지스터 118, 25 %)** 에 묶여 있었다
(DRAM 피크의 11 %, V100 에서는 FP64 연산 피크의 55 %). 세 가지를 구현해 V100 gpu04 에서 기여를 분리했다 (`apps/rbc_nob/scalability/sbatch_rhs_variants.sh`, `sbatch_rhs_r1only.sh`).

| 최적화 | 무엇 | 어디 |
|---|---|---|
| 1 역수 | 격자 간격 나눗셈 `/dx`·`/dmx`(162회) + `face_blend`(30회)를 `grid::Axis1D::inverse_*` 배열 곱으로 | `momentum_stencil.hpp` `rhs_*_cell`, `grid.{hpp,cpp}` |
| 2 coarsening | 스레드 하나가 j 방향 셀 K개 (`__restrict__` + unroll 로 j±1 로드 재사용) | `rhs.cu` `build_rhs_kernel<Component,K>`, 상수 `kCoarsenJ` |
| 3 전용 빌드 | `momentum::build_variable_property_rhs`: fill·이송확산 ×3·부력·∇P 8 패스 → 성분당 1 패스 (덧셈 순서 유지) | `rhs.{hpp,cu,cpp}`, `main.cpp` |

|---|---|---|---|---|---|---|
| 256³ strong np 1 | 17.3 | 8.70 | **7.02** | 7.14 | 7.77 | −8.6 / −1.7 / +0.1 |
| 256³ strong np 4 | 4.37 | 2.11 | **1.35** | 1.43 | 1.61 | −2.3 / −0.8 / +0.1 |

- **1(역수)이 절반**, 3(융합)이 다시 20 %, 2(coarsening)는 레지스터 118 → 164 로 점유율만 떨어뜨려 **손해 → 기본 K = 1(끔)**. 합계 ×2.5.
- step_total: 256³ np 1 118.6 → 108.3 (−9 %), 512³ np 2–8 −6~7 %.
- 게이트: 역수 때문에 비트 동일이 아니라 허용오차(`check_gate.py`) — 스모크 FINAL·200 스텝 모니터 전 조합 일치.
- H200 은 측정 못 함 (H200 잡은 배정되지 않아 취소 — 사용자 결정). 추정: 나눗셈 비중이 작은 H200 에서는 1 의 효과가 V100 보다 작다.

## 2e. 조립·커플링·scalar 스텐실 역수 (2026-10-17 밤 9) — 나눗셈 제거를 나머지 스텐실로 확장

2d 에서 역수가 절반을 먹은 것을 보고, 같은 격자 나눗셈을 쓰는 나머지 스텐실에도 `grid::Axis1D::inverse_*` 배열 곱을 적용했다. 수식·덧셈 순서는 그대로, 나눗셈만 곱으로.

| 어디 | 무엇 | 파일 |
|---|---|---|
| momentum ADI 조립 | `sweep_band`·`own_face_blend`(스윕 축·own 축 `/dx`·`/dmx` 28회) | `momentum_stencil.hpp`, `momentum/system/system.{cu,cpp}` (`DeviceAxes`·`OwnSpec` 에 idx·idmx) |
| momentum 커플링 4개 | `couple_rhs_v/w`, `block_couple_v/u` 셀 스텐실 (`face_blend` 32회 + 나눗셈 42회) | `momentum_stencil.hpp`, `momentum/solve_kernels.{cu,cpp}` |
| scalar 조립 | `axis_band` (`/dmx_lo`·`/dmx_hi` 20회, `/dx_c` 3회) | `scalar_stencil.hpp`, `scalar/system/system.{cu,cpp}` |

게이트: 허용오차 게이트(`check_gate.py`) — 스모크 FINAL(θ_c 0.01503 / Nu 46.0360)과 모니터 전 열이 `v100r1` 과 출력 정밀도에서 일치. 꼬리표 `v100s`
(`v100r2` 는 2d 의 K=2 변형이 이미 쓰고 있어 피했다). V100 gpu04. np 1 은 4장 잡(936000), np 2·4 는 4장 잡 두 개가 gpu04 를 **동시에** 쓴 상태(사용자: 그대로 진행),
np 8 은 8장 독점 잡(936004).

커플링이 가장 크게 준 이유: 셀당 `face_blend` 8개 + 나눗셈 10여 개가 전부 FP64 나눗셈이었고 메모리보다 연산에 묶여 있었다. 조립은 밴드 쓰기(메모리)가 섞여 있어 이득이 작다.

누적 (원본 → 최종 `v100s`, V100 256³ np 1): 198 → **100.1 ms (×1.98)**. 2c 표의 "후" 열은 `v100h` 기준이라 이 수치가 최신이다.

## 3. 결론

점유율 1위·손실 1위가 모두 **momentum_solve** → 이것부터 쪼개서 보고 최적화한다. → `momentum_scalability.md`, 그 다음 `scalar_scalability.md`.

노트북 `apps/rbc_nob/plot/main_scalability.ipynb` (momentum·scalar 도 같은 양식): §A 최적화 전 — 이벤트별 막대(np 나란히) → 이벤트별 scaling 곡선,
§B 최적화 후(최신 바이너리) — 같은 그림, §C 이벤트별 scaling 곡선에 전(큰 빈 ○, 파선)·후(작은 채운 ■, 실선) 겹치기, §D 전 vs 후 이벤트별 전/후 막대 + 감소량 막대 + 요약표, (main 만) §E halo 수정 직전(`h200z`·`v100z`) vs 최종 — np 8 통신 효과, §F momentum_rhs 직전(`v100h`) vs 후, §G 스텐실 역수 직전(`v100r1`) vs 최종(`v100s`).
제목·범례는 환경 파일에서 읽은 실제 기종·노드·꼬리표 + 문제 크기. 그림은 저장하지 않는다.

(다노드 잡은 이 큐에서 배정되지 않고 A100 8 GPU 잡도 잡히지 않아 포기 — 측정은 H200·V100 np ≤ 4 와 A100 np 1 로 닫는다.)
