## 1. 메모리 레이아웃과 루프 순서

모든 3차원 배열(필드·격자 보조 배열)은 같은 규칙이다:

```
선형 인덱스  idx(i, j, k) = (i * ny_total + j) * nz_total + k

보폭:  k → 1        (메모리에서 가장 빠르다)
       j → nz_total
       i → ny_total * nz_total   (가장 느리다)
```

**루프는 항상 `for i → for j → for k` (k 가 가장 안쪽).** 안쪽 루프가 연속 메모리를
걷게 하기 위해서다. 뒤집으면 같은 일에 얼마나 느려지는지 실측 (256³ double 합,
login01, g++ -O2, 2026-10-03):

```
ijk (k 안쪽 = 연속 접근)      21.5 ms
kji (i 안쪽 = 매번 점프)     143.3 ms     ← 6.7 배
```

왜 k 를 가장 빠르게 두는가:
1. **z 방향 스윕이 지배적이다** — 벽수직(z) TDMA·ADI 스윕에서 한 z-라인(i, j 고정)이
   연속 메모리가 된다.
2. **검증된 수식의 1:1 이식** — MPM-STD_C 와 같은 레이아웃이라 Report/study/ref_03 의
   수식을 인덱스 재유도 없이 옮긴다 (계획 §5.4).
3. 비용은 z-halo 평면이 가장 흩어진 모양이 되는 것인데, 그건 `z_plane_type_`
   (subarray datatype) 이 흡수하고 통신량은 연산량보다 훨씬 작다.

## 2. ghost 와 배열 치수

```
n_total = n_local + 2 * halo_width        (halo_width = 1 — 모든 스텐실이 3점이라 충분)

축 인덱스:   0            1 ... n_total-2        n_total-1
           ghost         ├── 내부 (미지수) ──┤      ghost
```

- 내부 루프 관용구: `for (i = halo_width; i < nx_total - halo_width; ++i)`
- 전역 ↔ 로컬: `global = offset + (local − halo_width)` — 손으로 쓰지 말고
  `sub.z().global(k)` / `sub.z().local(gz)` / `sub.z().owns(gz)` 를 쓴다
  (halo_width 보정을 빠뜨리는 것이 MPM-STD_C 의 단골 off-by-one 이었다).
- ghost 를 채우는 주체는 둘이고 역할이 다르다:
  - **랭크 경계** → halo 교환 (`sub.exchange_halo(f.data())`) — 이웃 내부의 복사
  - **전역 경계(벽)** → 경계조건 모듈(M5)이 채움. 주기 축은 halo 교환의 랩이 처리
- halo 교환은 **면만** 바꾼다. 모서리(edge/corner)는 보증하지 않는다 — 스텐실이
  ±1 면만 읽는 동안은 충분하다.

## 3. MAC staggering — "각 성분은 자기 셀의 마이너스 면을 소유한다"

다섯 필드가 **전부 같은 모양**을 쓴다 (A안 — 계획 §5.1 확정). staggering 은 저장이
아니라 **해석**이다. 규칙은 하나:

```
              V(i,j+1,k)
          ┌──────▲──────┐
          │             │
U(i,j,k) ▶│  ● P,T(i,j,k)│▶ U(i+1,j,k)        U(i,j,k) 의 x 좌표 = grid.x.face[i]
          │             │                     P,T(i,j,k) 의 좌표 = grid.*.center[*]
          └──────▲──────┘
              V(i,j,k)                        (z 방향 W 도 동일한 그림)
```

셀 (i,j,k) 는 **중심값 P·T 하나와 마이너스 면 셋(U, V, W)** 을 소유한다.
플러스 면은 이웃 셀의 인덱스로 부른다: 셀 i 의 +x 면 = `U(i+1, j, k)`.

### "면이 셀보다 하나 많은데 배열 크기가 같은" 이유

z 축(벽)을 1차원으로, 내부 4셀 + ghost 2셀 = `n_total 6` 으로 그리면:

```
 셀 번호:     0        1        2        3        4        5
           (ghost)  (내부1)  (내부2)  (내부3)  (내부4)  (ghost)
          ┌───────┬───────┬───────┬───────┬───────┬───────┐
 면 번호:  0       1       2       3       4       5       6
                   ↑하단 벽                        ↑상단 벽
 W 슬롯:  W[0]    W[1]    W[2]    W[3]    W[4]    W[5]     ✗ 저장 안 함
```

- 기하학적 면은 7개지만 **슬롯은 셀당 1개(자기 마이너스 면) = 6개**다.
- 남는 면 하나(면 6)는 **마지막 ghost 셀의 플러스 면** — ghost 셀에서는 연속방정식을
  풀지 않으므로 어떤 스텐실도 읽지 않는다. 버려도 된다.
- 수지: 도메인 안의 면 5개(벽 2 + 내부 3) + 바깥 면 1개(면 0) = 슬롯 6개. ✓

### 미지수 범위와 스텐실이 정확히 맞물린다

```
 슬롯:        0      1      2      3      4      5     │  (6)
            halo  ├──── 미지수 (내부) ────┤   halo     │ 없음
 i=1 스텐실:  [0]───[1]───[2]
 i=4 스텐실:                 [3]───[4]───[5]
 ──────────────────────────────────────────────
 스텐실 합집합 = 0~5 = 배열 전체.  면 6 은 "i=5 의 스텐실"에만 필요한데
 i=5 는 미지수가 아니다 (주기면 랩 복제, 벽이면 경계값).
```

`n_total = 미지수 + 양쪽 halo 한 겹` — 이것이 배열 치수의 진짜 의미다.

### ⚠ 벽면의 비대칭 (z 벽 축에서)

- **하단 벽면 = W 의 내부 슬롯** `W(i, j, halo_width)` — TDMA 스윕의 내부 행에
  걸리므로 명시적으로 처리해야 한다 (M7+ 에서 `zero_wall_faces` 같은 **이름 있는
  함수로만** 접근 — raw `k=h` 인덱스를 호출부에 노출하지 않는다).
- **상단 벽면 = W 의 ghost 슬롯** `W(i, j, nz_total - halo_width)` — 스윕 범위 밖이라
  자동 제외, 값만 넣어 주면 된다.
- 같은 인덱스가 필드마다 다른 위치라는 점 주의: `W(i,j,5)` 는 상단 **벽 위**
  (z = lz), `P(i,j,5)` 는 **벽 밖** ghost 중심이다 (위 그림의 면 5 vs 셀 5).

## 4. 랭크 분해와 면 소유권

분해는 **셀 단위**다 (`split_evenly` — PaScaL para_range 와 동일, 앞 랭크가 나머지를
먼저 받는다). 면의 소유권은 셀에서 상속된다: **각 전역 면은 그 면을 마이너스 면으로
갖는 셀의 랭크가 푼다.** 전역 8셀을 2랭크로 나누면 (면 번호는 §3 그림과 동일):

```
전역 셀:     [g0]  1   2   3   4   5   6   7   8  [g9]     [..] = 전역 ghost
rank 0  셀  [g0]  1   2   3   4  [5]     ← [5] = 이웃 복제 (halo)
rank 1          [4]  5   6   7   8  [g9]

면 1~4 : rank 0 이 푼다          면 5~8 : rank 1 이 푼다
면 9   : 상단 벽 — 아무도 안 푼다 (경계값; rank 1 의 ghost 슬롯에 수납)
겹친 두 칸(셀 4, 5)은 "소유자 1 + 차용자 1" — 중복도 누락도 없다.
```

랭크 경계는 벽이 아니라 이음새다: 이웃 판정은 `topo.z().minus_neighbor /
plus_neighbor` 하나로 하고, `MPI_PROC_NULL` 이면 그쪽이 **전역 벽**이다.
(벽에서는 `MPI_Sendrecv` 가 자동 no-op — 분기문을 쓰지 않는다.)

격자도 같은 원리다: **전역 면 좌표를 먼저 만들고 랭크 몫을 자른다** — 그래서 랭크
수를 바꿔도 격자·분할이 비트 단위로 동일하다 (test_grid 가 보증; 분해 독립 재시작의
전제).

## 5. 축을 코드에서 다루는 법 (D13)

- **축 매개변수화 금지.** 스텐실·스윕·halo 교환은 x/y/z 블록을 따로 쓴다.
  축 데이터는 명명 멤버로 집는다: `grid.z.cell_width[k]`, `topo.z().plus_neighbor`,
  `sub.z().n_local`. `Axis`/`Direction` enum 은 없다.
- 공유해도 되는 것은 **스칼라만 받는 수식 함수**뿐이다 (축을 인자로 받는 함수 금지).
- 근거: MPM-STD_C 의 `own_dir` 분기 616줄 커널이 읽기를 막은 주범이었다
  (MPM-STD_C/Report/study/ref_03 §1.2).

## 6. 경계조건의 두 반쪽 — ghost 채움 ↔ 행렬 fold 쌍

음해(implicit) 풀이에서 벽 행은 ghost 를 참조하지만, ghost 는 독립 미지수가 아니라
**내부 미지수의 함수**다. 그 관계식을 대입해 ghost 를 소거하는 것이 fold 이고,
같은 경계조건을 명시 반쪽(ghost 값)과 음해 반쪽(fold)이 각각 표현한다.
**쌍이 어긋나면 벽의 물리가 바뀐다** — MPM-STD_C 실화: 모든 Dirichlet 에
`B += A` 를 적용 → 의도치 않은 Neumann 벽 → no-slip under-damped →
PaScaL_TCS 운동량 검증 불일치.

| ghost 함수 (boundary/wall.hpp) | ghost 관계식 | δ-관계식 | fold (M7, 각 방정식 z-블록) |
|---|---|---|---|
| `fill_z_wall_mirror` | g = 2v − f₁ | δg = −δf₁ | `B −= A` (D 불변) |
| `fill_z_wall_value` | g = v | δg = 0 | A 만 제거 (B, D 불변) |
| `fill_z_wall_zero_gradient` | g = f₁ | δg = +δf₁ | `B += A` (D 불변) |
| `zero_z_wall_faces` (W) | 벽면 = 0 | δ벽면 = 0 | 하단 벽면 행 = 항등행 (상단은 스윕 범위 밖) |

"D 불변"은 delta-form + **벽값 상수** 덕이다. (CaNS 는 전체 변수를 풀므로 같은
상수항을 `bc_rhs` 벡터로 매 솔브 더한다 — 수학적으로 동일, 부기만 다름.)

### 시간 가변 벽값 v(t) 체크리스트

바꿀 곳은 정확히 두 곳:
1. **ghost 채움 — 수정 불필요.** 매 스텝 그 시점 값을 인자로 넘기면 된다.
2. **fold — 벽 행 RHS 에 항 추가** (Δv = vⁿ⁺¹ − vⁿ):
   mirror `D −= 2Δv·A` · value `D −= Δv·A` · 구배 g(t) `D += A·(중심간거리)·Δg`

참고: CaNS 도 `rhsb` 를 initsolver 에서 1회만 계산하므로 그대로는 v(t) 를 못
다룬다 — 양쪽 다 "벽값 상수"가 기본 가정이다. 비영 Neumann 을 만들 때는 반드시
격자 간격(center_distance)을 곱할 것 (CaNS `set_bc` 의 `dr` 방식; MPM-STD_C 는
안 곱해서 "value = Δφ" 함정이 있었다).
